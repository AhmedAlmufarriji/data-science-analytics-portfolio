# Security Policy

This repository contains **educational source code and non-production prototypes**, not customer-facing hosted services. Please do not use demos to process real personal, insurance, banking or payment information.

## Supported code

Security reports concerning the current `main` branch are welcome. Archived examples and third-party dependencies may have different update schedules; no formal service-level agreement is offered.

## Reporting a vulnerability

**Please do not publish exploitable details, personal data, passwords, access tokens or working credentials in a public issue.**

If GitHub's **Report a vulnerability** / private vulnerability reporting option is enabled for this repository, use that option.

If private vulnerability reporting is not available, open a **non-sensitive** issue stating that you need a private disclosure channel. Do not include reproduction steps, exploit code, affected user data or secrets until a secure communication path is established.

A useful private report should include:

- Affected file or component and tested revision
- Security impact and conditions needed to reproduce
- Minimal, non-sensitive reproduction steps
- Whether the issue could affect anyone beyond a local educational demo
- Suggested remediation, if known

Reports are reviewed when available; this is an individual portfolio, not a staffed 24/7 security operation.

## Boundaries

- Do not submit personal records or confidential company information.
- Do not hard-code API credentials into demonstrations or documentation.
- No component should be assumed to connect to actual Najm, banking, government or client systems.
- Published research and teaching data do not imply authorization for production use.
